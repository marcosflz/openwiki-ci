# Files

- [Configuration and environment variables](configuration.md) - Reference of the service-owned Settings fields (defaults, effect, grouped by domain), the validators and invariants they enforce, the variables the service forces on the OpenWiki subprocess, and how data_dir, jobs_dir and resolved_config_dir are derived.
- [Deployment: Docker image, compose and horizontal scaling](deployment.md) - How the service is built and run - the Python 3.12 + Node 22 image with the OpenWiki CLI baked in via the OPENWIKI_VERSION build arg, the api and worker services of docker-compose.yml sharing the openwiki-ci-data volume, scaling with --scale worker, healthcheck behaviour and the single-container mode.
- [Observabilidad, mantenimiento y límites conocidos](observability-and-recovery.md) - Todas las señales de diagnóstico que expone el servicio y su origen: el bloque pasivo pool y model de /health, la sonda cacheada de /health/model, los campos de WikiView, el progreso leído de openwiki/.run.json, los logs con timestamp y redactados, push_result y errores truncados, además de las tareas periódicas (purge_expired, recover_stale, prune_workers), las rutas de recuperación cuando se pierde un workspace o un worker, y los límites MVP declarados.
- [Repository wiki refresh workflow (GitHub Actions)](wiki-refresh-workflow.md) - The scheduled GitHub Actions workflow .github/workflows/openwiki-update.yml that refreshes this repository's own openwiki/ wiki with the OpenWiki CLI in update mode and opens a pull request: triggers, permissions, fetch-depth 0, the pinned CLI version and provider secrets, the openwiki/.run.json cleanup, the paths included in the PR, failure propagation, and the contracts it fixes with AGENTS.md, CLAUDE.md and openwiki/INSTRUCTIONS.md. It is also the repository's only CI job, and it does not run the test suite.
